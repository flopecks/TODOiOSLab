Antes de empezar

Vas a completar una app nativa de tareas con Swift + SwiftUI. Ya tiene interfaz, datos de ejemplo y borrado. Al inicio, agregar y completar todavía no hacen nada, y el contador muestra 0: esas son tus misiones. El proyecto compila desde el inicio.

Abre TODOiOSLab.xcodeproj en la raíz de tu copia. Trabajarás en ese proyecto durante todo el laboratorio.

  • Necesitas una Mac con Xcode 27.1 y sus componentes preparados. Antes de empezar, comprueba que tienes un runtime iOS Simulator instalado. Si falta y hay espacio, pide ayuda al encargado para instalarlo desde Xcode → Settings → Components; prepara la descarga y el primer arranque antes de comenzar.
  • En simulador no necesitas Apple Account ni membresía de Apple Developer. Si falta espacio para el runtime, puedes elegir usar tu iPhone siguiendo la alternativa de iPhone y privacidad. También puedes pedir una Mac preparada o trabajar en pareja.
  • Git viene con las herramientas de Xcode. No necesitas instalar Homebrew, CocoaPods, gestores de paquetes ni GitHub CLI.
  • Este codelab y el recorrido en simulador funcionan offline después de preparar Xcode y su runtime. El fork, el token, el push y el PR requieren GitHub; la preparación inicial de un iPhone y su firma pueden requerir internet.

Tu meta: personaliza la app, completa los cuatro ejercicios, guarda al menos tres commits y entrega un PR dentro de tu fork con una captura. Puedes aprobar el laboratorio sin hacer el reto opcional de SwiftData.

Tu fork, tu copia y tu rama

En el navegador: abre el enlace del repositorio que recibiste para esta práctica. Inicia sesión en GitHub (mejor en ventana privada), pulsa Fork → Create fork y elige tu cuenta como propietaria. Conserva el nombre TODOiOSLab. Comprueba que tu fork contiene la rama main; si la interfaz ofrece copiar solo la rama predeterminada, verifica que sea main o desmarca esa opción. Si no aparece esta rama, detente y avisa al encargado. En tu fork, usa Code → HTTPS para copiar su dirección.

Las líneas que empiezan con # explican qué hace el siguiente comando. Léelas primero y ejecuta en Terminal solo las líneas que no empiezan con #.

Clona tu fork y crea tu rama de trabajo. Abre Terminal desde Spotlight (⌘ Espacio) y ejecuta estos comandos uno por uno. Sustituye TU_USUARIO por tu usuario de GitHub y mi-nombre por tu alias sin espacios ni tildes. Si cambiaste el nombre del fork, utiliza su URL y carpeta reales.

# Crea una carpeta para guardar tu práctica.
mkdir -p ~/Documents/LaboratorioIOS

# Entra en la carpeta de trabajo.
cd ~/Documents/LaboratorioIOS

# Descarga la rama main de tu fork a esta Mac.
git clone --single-branch --branch main https://github.com/TU_USUARIO/TODOiOSLab.git

# Entra en tu copia del repositorio para ejecutar los siguientes comandos.
cd TODOiOSLab

# Comprueba que origin apunta a tu fork en GitHub.
git remote -v

# Crea tu rama de trabajo y cámbiate a ella.
git switch -c lab/mi-nombre

Explicación

origin debe apuntar a tu fork. clone crea una copia local; switch -c crea tu rama de trabajo.

Configura la identidad de tus commits y tu acceso a GitHub solo en esta copia. En GitHub → Settings → Emails puedes copiar tu dirección noreply si prefieres no publicar tu correo personal. Sustituye ambos ejemplos:

# Define el nombre que aparecerá en tus commits de este repositorio.
git config --local user.name "Tu nombre o alias"

# Define el correo que identificará tus commits.
git config --local user.email "TU_CORREO_VERIFICADO_O_NOREPLY"

# Evita que esta copia use el llavero para guardar el token.
git config --local credential.helper ""

# Indica tu usuario de GitHub para la autenticación.
git config --local credential.username "TU_USUARIO"

# Revisa en qué rama estás y qué archivos tienen cambios.
git status

Explicación

El helper vacío evita que esta copia use el llavero para guardar el token. No cambia la configuración global de la Mac. El nombre y correo identifican tus commits; no te autentican.

Prepara un token temporal para el push
  1. Después de crear el fork, en GitHub abre tu foto → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token.
  2. Nombre: Laboratorio iOS. Vencimiento: 1 día o la fecha más cercana que permita la interfaz. Resource owner: tu cuenta.
  3. Repository access: Only select repositories y selecciona únicamente tu fork TODOiOSLab.
  4. Repository permissions: Contents → Read and write. Metadata de lectura se agrega automáticamente. No agregues permisos de administración. El PR se crea en el navegador, por lo que no necesitas permisos de Pull requests en el token.
  5. Genera el token cuando estés listo para usarlo. GitHub lo muestra una sola vez: si cierras la página sin conservarlo, revócalo y genera otro al hacer push. No lo pegues en archivos, capturas, comandos ni en la URL del repositorio. Solo se pega en el prompt Password de Git; no verás caracteres al pegar.

También puedes abrir directamente este formulario de token con nombre, duración y permiso prellenados. Antes de generar el token, comprueba que el propietario sea tu cuenta y selecciona únicamente tu fork.

Comprueba: git status indica lab/tu-alias; git remote -v muestra la URL de tu fork con tu usuario.

2 · Agrega una tarea

Abre TodoScreen.swift. Busca LAB 2 dentro de addTodo(). Para agregar la tarea a la lista y limpiar el campo de texto, escribe estas dos líneas debajo del comentario. Conserva la validación existente:

todos.append(Todo(title: title))
newTodoText = ""

Revisa la función completa. Compara tu addTodo() con este bloque para comprobar que conservaste la validación y añadiste las dos líneas en el lugar correcto:

private func addTodo() {
    let title = newTodoText.trimmingCharacters(in: .whitespacesAndNewlines)
    guard !title.isEmpty else { return }
    todos.append(Todo(title: title))
    newTodoText = ""
}

Explicación

  • trimmingCharacters quita espacios al principio y al final.
  • guard sale temprano si el título está vacío.
  • Todo(title: title) construye una tarea usando un argumento con nombre.
  • append agrega al arreglo, como add en una lista mutable de Kotlin.
  • @State conecta los cambios de todos y newTodoText con lo que ves.

En TextField(..., text: $newTodoText), $ entrega un Binding: el campo lee y escribe el mismo estado. En Compose harías algo parecido con value y onValueChange.

Ejecuta, escribe “Aprender Swift con Andrea” y pulsa +. Prueba también la tecla Done/Intro. El contador todavía no es correcto; lo resolverás en el paso 4.

3 · Completa y reabre tareas

En toggleTodo(id:), busca LAB 3. Para alternar la tarea entre pendiente y completada, reemplaza _ = index y su comentario por esta línea:

todos[index].isDone.toggle()

Revisa la función completa. Tu toggleTodo(id:) debe conservar la búsqueda por identificador y cambiar el estado de la tarea encontrada:

private func toggleTodo(id: UUID) {
    guard let index = todos.firstIndex(where: { $0.id == id }) else { return }
    todos[index].isDone.toggle()
}

Explicación

UUID identifica una tarea. firstIndex busca su posición, y devuelve un opcional porque podría no existir. guard let obtiene la posición si existe o sale de la función. Dentro de la closure, $0 significa “el elemento actual”, parecido a it en Kotlin.

toggle() invierte un booleano: true pasa a false y viceversa. TodoRow ya dibuja el círculo y el tachado según isDone.

Comprueba: pulsa el círculo de una tarea. Se rellena y el texto se tacha. Pulsa de nuevo y vuelve a pendiente. El botón de basura debe borrar únicamente esa tarea.

4 · Cuenta las pendientes

Busca LAB 4, cerca del inicio de TodoScreen.swift. Para contar las tareas pendientes, reemplaza el 0 dentro de remainingCount por todos.filter { !$0.isDone }.count. La propiedad completa debe quedar así:

private var remainingCount: Int {
    todos.filter { !$0.isDone }.count
}

Explicación

Es una propiedad calculada: filtra las tareas cuyo isDone es falso y cuenta el resultado. ! significa “no”. Calcula el contador a partir de la lista, sin guardar otro estado: así evitas que el número de pendientes se descoordine con las tareas. Una propiedad con una sola expresión puede omitir return.

Reto opcional · SwiftData

Primero entrega el recorrido principal. Realiza este reto si ya entregaste la práctica y quieres explorar la persistencia. El modelo @Model, el contenedor, @Query y el manejo de errores ya están preparados. SwiftData es un framework de Apple incluido con Xcode; no requiere dependencias externas ni cuenta en la nube.

  1. Activa la pantalla con persistencia. En LabSettings.swift, cambia usesPersistence a true:
static let usesPersistence = true

Explicación

La app mostrará otra pantalla, con la misma apariencia y una lista persistente inicialmente vacía. Las tareas del ejercicio con @State no se migran. Ambas pantallas son independientes.

  1. Registra las tareas nuevas en SwiftData. En Persistence/PersistentTodoScreen.swift, agrega esta línea debajo de EXTRA 2:
modelContext.insert(StoredTodo(title: title))
  1. Registra el borrado de tareas en SwiftData. En el mismo archivo, agrega esta línea debajo de EXTRA 3:
modelContext.delete(todo)

Explicación

modelContext registra las inserciones, cambios y eliminaciones; saveChanges() ya guarda y muestra un mensaje si falla. @Query obtiene las tareas guardadas y actualiza la lista. El botón de completar ya modifica el modelo y lo guarda. createdAt mantiene el orden de creación.

  1. Ejecuta, agrega dos tareas y completa una. Detén con ■ en Xcode y vuelve a ejecutar en el mismo simulador o iPhone. Deben conservarse los títulos y la tarea completada.
  2. Elimina una, detén y ejecuta de nuevo. La tarea eliminada no debe regresar.
  3. No desinstales la app ni borres el simulador: eso puede eliminar su almacenamiento. No se sincroniza entre simuladores o teléfonos. En iPhone, el texto preparado de la app puede decir “este simulador”; se refiere al almacenamiento local del destino donde la ejecutas.

Haz un commit del reto de SwiftData y súbelo a GitHub. Después de comprobar la persistencia, ejecuta estos comandos en Terminal para guardar los dos archivos modificados y actualizar tu PR:

Explicación
