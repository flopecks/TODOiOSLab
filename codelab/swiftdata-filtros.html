Qué vas a construir

Una extensión de la app de iOS que conserva tareas al cerrar el proceso y permite elegir Todas / Pendientes / Completadas. El modelo, contenedor SwiftData, consulta, selector y manejo de errores están preparados; completarás cuatro líneas de lógica y tu personalización.

Necesitas Xcode 27.1 y un simulador iOS instalado previamente (iOS 17 o posterior compatible), o el iPhone que ya preparaste en el primer día. Para un teléfono nuevo, consulta la guía de preparación y privacidad antes de la clase. No instales herramientas durante el laboratorio.

La base no exige haber completado el reto anterior. Usa otra identidad de app y comienza con una base de datos vacía; no altera ni importa tareas del primer día. Al principio Agregar y Eliminar no modifican datos, y los tres filtros muestran lo mismo. Es intencional.

Todo funciona con SwiftUI y SwiftData incluidos en Xcode. No hay servidor, cuenta en la nube, paquetes, migraciones ni sincronización entre dispositivos. La guía y la app funcionan offline; GitHub requiere conexión.

1 · Guarda una tarea

Abre TODOiOSLab/Persistence/PersistentTodoScreen.swift. Busca DATOS 2 dentro de addTodo() y agrega:

modelContext.insert(StoredTodo(title: title))

La función completa queda así:

private func addTodo() {
    let title = newTodoText.trimmingCharacters(in: .whitespacesAndNewlines)
    guard !title.isEmpty else { return }
    modelContext.insert(StoredTodo(title: title))
    if saveChanges() { newTodoText = "" }
}

StoredTodo es el modelo preparado con @Model. modelContext.insert registra una tarea nueva. saveChanges() ya llama a save(), atiende errores y solo limpia el campo si se guardó. @Query obtiene los modelos y actualiza la lista.

Ejecuta, agrega “Aprender persistencia” y “Preparar mi entrega”; completa una con el círculo. Detén con ■ en Xcode y ejecuta de nuevo en el mismo dispositivo. Los títulos y la tarea completada deben permanecer. Ir a Home solo pone la app en segundo plano; no prueba este caso.

Comprueba: después de detener y ejecutar, ves dos tareas y una completada. La lista en memoria del día uno perdía estos cambios; esta lista los guarda en disco.

2 · Elimina de forma persistente

En el mismo archivo, busca DATOS 3 dentro de deleteTodo. Agrega:

modelContext.delete(todo)

La función queda así:

private func deleteTodo(_ todo: StoredTodo) {
    modelContext.delete(todo)
    saveChanges()
}

Eliminar una fila de un arreglo temporal no basta para borrar un registro persistente. Aquí marcamos la eliminación en el contexto y guardamos. El botón de completar ya hace algo equivalente: modifica el modelo y guarda.

Borra una de tus tareas, detén y ejecuta. La tarea no debe regresar. No desinstales la app ni borres el simulador para probarlo; eso eliminaría su almacenamiento.

git add TODOiOSLab/LabSettings.swift TODOiOSLab/Persistence/PersistentTodoScreen.swift
git commit -m "Personaliza y guarda altas y bajas con SwiftData"

Comprueba: el borrado se conserva después de relanzar y el contador coincide con las tareas que quedan.

3 · Muestra solo lo que necesitas

En la parte superior de PersistentTodoScreen.swift ya existe TodoFilter. Es un enum con tres opciones. El Picker preparado guarda la elección en @State selectedFilter.

Busca DATOS 4A y DATOS 4B dentro de visibleTodos. Reemplaza solamente el return todos de cada uno. Deja intacto el caso .all:

private var visibleTodos: [StoredTodo] {
    switch selectedFilter {
    case .all:
        return todos
    case .pending:
        return todos.filter { !$0.isDone }
    case .completed:
        return todos.filter { $0.isDone }
    }
}

switch elige una expresión según el filtro. $0 es la tarea que se está evaluando; no es el mismo uso del signo $ que un Binding. ! significa “no”. filter construye una selección del arreglo: no elimina registros de SwiftData.

La lista ya usa ForEach(visibleTodos). El contador de la cabecera siempre cuenta toda la base; “Mostrando…” cuenta solo las filas del filtro. Es una diferencia intencional. Para una lista pequeña filtramos en memoria lo que lee @Query; no abordaremos consultas avanzadas en este laboratorio.

Crea tres tareas y completa una. Todas muestra 3, Pendientes muestra 2, Completadas muestra 1. En Pendientes, completa una: desaparecerá de ese filtro pero seguirá en Completadas. Regresa a Todas para comprobar que no se perdió.

git add TODOiOSLab/Persistence/PersistentTodoScreen.swift
git commit -m "Filtra tareas por estado sin borrar datos"

Comprueba: cada opción muestra los registros correctos y el total global se conserva.

Comprueba datos y filtros

  • Con dos pendientes y una completada: Todas 3, Pendientes 2, Completadas 1; cabecera “2 de 3 pendientes” en los tres casos.
  • En Pendientes, completa una tarea: cambia de filtro y el contador global baja.
  • En Completadas, reabre una: vuelve a Pendientes.
  • Borra una fila desde un filtro: solo se elimina ese registro.
  • Si un filtro no tiene coincidencias pero sí existen tareas, se muestra “No hay tareas en este filtro”; volver a Todas las recupera.
  • Solo espacios no permite agregar. Dos tareas con el mismo título siguen siendo registros independientes.
  • Detén y relanza: altas, estado y borrado se conservan. La selección del filtro vuelve a Todas porque es estado temporal.

Pregunta: ¿qué diferencia hay entre modelContext.delete y todos.filter? ¿Por qué la selección del filtro puede reiniciarse sin perder tareas?

Recordatorio de acceso temporal

En GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens, crea un token por un día, propietario tu cuenta, solo tu fork, permiso Contents: Read and write. Configura git config --local credential.helper "" para no guardarlo en el llavero. Si quieres el recorrido completo, consulta la guía del primer día. El token sirve para Git; el PR se crea con la sesión web. No reutilices el token vencido del primer laboratorio.

En GitHub abre tu fork → Pull requests → New pull request. Revisa que base repository sea TU_USUARIO/TODOiOSLab, base sea main, head repository sea tu mismo fork y compare sea tu rama de este laboratorio. Si GitHub propone el repositorio del docente como destino, cámbialo.

El PR contra main también puede mostrar la preparación de este laboratorio, porque partiste de una rama del docente: es esperado. En la descripción distingue tus cambios personales de la base preparada.

GitHub puede rellenar la plantilla del primer día porque la base es main. Abre .github/pull_request_template.md de tu rama actual (por ejemplo, con cat .github/pull_request_template.md en Terminal), copia su contenido y reemplaza la descripción del PR con esa plantilla de segunda sesión. Complétala, arrastra las capturas, espera a que carguen y revisa Preview. Comparte el enlace por el canal del curso y deja el PR abierto. Si aún existe el PR del día anterior, conserva ambos: esta entrega es un PR nuevo.

Antes de salir: verifica que el PR exista, revoca el token de hoy, cierra sesión de GitHub y las ventanas privadas; reemplaza el portapapeles por texto inocuo. Si no hay internet, conserva los commits y la captura: la entrega remota queda pendiente, no inventes un enlace.
